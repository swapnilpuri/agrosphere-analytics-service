Reviewed the exact SQL candidate referenced by ANL01_ADAPTER_REVIEW.md before runtime installation. This is engineering review within owner-directed continuation, not external/owner functional or production acceptance. No database was touched by this document.

Six service-owned tables store only minimal validated facts. Highest contributions are SIMULATED-only; pending/calculated/void source states preserve rounded mass and nullable DRC. Numeric aggregate columns avoid the individual collection magnitude cap and reject non-finite values. Source bounds remain numeric(9,3). Receipt and seen/issue identities prevent replay addition. Table/index names do not reference another service. V1 stays unchanged; the candidate becomes additive V2 only in the authorized runtime implementation.

Required transaction discipline: reserve event receipt before collection lock; canonical scope lock order before daily writes; reverse/apply all contributions atomically with receipt/seen/highest/issues/cursors; no ACK on uncertain commit. The schema alone does not enforce envelope equivalence, highest-version ordering, immutable attribution or gap closure: parser/domain/transaction tests must prove these. Seen-version FK is valid for highest-before-creation because the highest ledger is inserted before seen rows in one transaction. Zero-root cached buckets must map to NONE, not observed zero production. Reads use repeatable-read snapshots.

Generated-only grants: migration owner owns DDL; runtime SELECT/INSERT on anl_receipt/anl_seen_version/anl_issue, SELECT/INSERT/UPDATE on anl_collection/anl_scope/anl_daily; no schema CREATE, TRUNCATE, receipt/seen/issue UPDATE/DELETE or PUBLIC function grants. Owned fixture rebuild replaces only cached daily rows using bounded owned-state checks; no existing-target reset. Separate generated migration/runtime LOGINs and real authentication/denial tests are required.
